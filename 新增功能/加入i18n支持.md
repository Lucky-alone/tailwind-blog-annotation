# i18n 中英文切换功能

## 功能概述

为 Tailwind Next.js Starter Blog 添加了完整的中英文国际化（i18n）支持。用户在 Header 导航栏右侧可以通过语言切换按钮（显示"语言"二字）在 English 和中文之间自由切换。语言偏好会通过 localStorage 持久化存储，刷新页面后仍保持用户选择。

所有 UI 文本均已支持 i18n，包括：
- 导航链接（Home/Blog/Tags/Projects/About）
- 页面标题和描述
- 分页控件
- 搜索按钮和搜索面板（KBar 全部文本：占位符、分组标题、加载状态、无结果提示、日期格式）
- 文章布局（发布日期、标签、前后篇导航）
- 项目卡片（Learn more、aria-label）
- 主题切换菜单
- 404 页面
- 页脚信息
- 所有 aria-label 无障碍文本

## 技术选型及原因

### 采用方案：React Context + localStorage

本方案不依赖任何外部 i18n 库，完全基于 React 原生能力实现：

| 技术要素 | 说明 |
|---------|------|
| React Context | 管理全局语言状态，所有子组件可访问 |
| localStorage | 持久化用户的语言偏好 |
| TypeScript 翻译字典 | 类型安全的键值对翻译映射 |
| Headless UI Menu | 语言切换下拉菜单 |

### 选择原因

1. **轻量级**：不引入 `next-intl`、`next-i18next` 等外部库，不增加 bundle 体积
2. **简单场景**：仅需支持 2 种语言（中/英），不需要 URL 路由级别的多语言（如 `/en/blog`、`/zh/blog`）
3. **兼容性好**：与现有 Next.js App Router 的 Server/Client Component 架构完全兼容
4. **易于扩展**：添加新语言只需新增一个翻译字典文件

## 核心实现原理

### 1. LocaleProvider（`components/locale-provider.tsx`）

核心上下文组件，负责：
- 创建 `LocaleContext` 提供 `locale` 和 `setLocale`
- 客户端挂载后从 `localStorage` 读取语言偏好
- 语言切换时同步写入 `localStorage`
- 未挂载前默认返回英文，避免 SSR 水合不匹配

### 2. useTranslation Hook

```typescript
export function useTranslation() {
  const { locale } = useLocale()
  const dict = translations[locale]
  const t = (key) => dict[key] || key  // 键名作为后备
  return { t, locale }
}
```

在任何需要翻译的客户端组件中使用：
```tsx
const { t } = useTranslation()
return <h1>{t('home.latest')}</h1>
// 英文: "Latest" | 中文: "最新文章"
```

### 3. LocaleSwitch（`components/LocaleSwitch.tsx`）

- 使用 Headless UI 的 `Menu` 组件实现下拉菜单
- 显示"语言"二字文本作为语言切换入口（不使用图标）
- 提供 English / 中文 两个选项
- 当前选中的语言以加粗样式高亮
- 使用 `mounted` 状态避免服务端/客户端水合不匹配

### 4. 导航链接翻译

Header 和 MobileNav 中的导航链接通过 `NAV_TRANSLATION` 映射表实现翻译：

```typescript
const NAV_TRANSLATION: Record<string, string> = {
  '/': 'nav.home',
  '/blog': 'nav.blog',
  '/tags': 'nav.tags',
  '/projects': 'nav.projects',
  '/about': 'nav.about',
}
```

渲染时优先使用翻译，若 href 无对应翻译则回退到原始标题：
```tsx
{NAV_TRANSLATION[link.href] ? t(NAV_TRANSLATION[link.href]) : link.title}
```

### 5. 翻译字典（`data/i18n/en.ts`、`data/i18n/zh.ts`）

采用命名空间键值对格式，共 96 个翻译条目：
```typescript
{
  'nav.home': 'Home',           // 导航
  'nav.toggleMenu': 'Toggle Menu',
  'home.latest': 'Latest',      // 首页
  'blog.previous': 'Previous',  // 博客
  'post.tags': 'Tags',          // 文章布局
  'search.label': 'Search',     // 搜索按钮
  'search.placeholder': 'Type a command or search...', // 搜索面板
  'search.content': 'Content',  // 搜索分组
  'search.noResults': 'No results for your search...', // 无结果
  'notFound.message': '...',    // 404 页面
  'theme.light': 'Light',       // 主题
}
```

### 6. 自定义 KBar 搜索（`components/KBarSearch.tsx`）

替代 pliny 库的 SearchProvider，解决 pliny 搜索面板中硬编码英文文本的问题：

| 原文（pliny 硬编码） | 中文翻译 |
|---------------------|---------|
| Type a command or search... | 输入命令或搜索... |
| Content | 内容 |
| Loading... | 加载中... |
| No results for your search... | 未找到相关结果... |
| 日期格式 en-US | 日期格式 zh-CN |

实现方式：
- 直接使用 `kbar` 库组件构建搜索面板，完全控制所有 UI 文本
- 通过 `useSearchActions` hook 加载搜索文档并注册为 kbar actions
- 使用 `useTranslation` 获取翻译后的分组标题和日期格式
- 导出 `useKBarSearch` hook 供 SearchButton 触发搜索面板

## 如何扩展新语言

### 步骤 1：创建翻译字典

在 `data/i18n/` 下新建语言文件，如 `ja.ts`（日语）：

```typescript
import en from './en'

const ja: typeof en = {
  'nav.home': 'ホーム',
  'nav.blog': 'ブログ',
  // ... 其他翻译
}

export default ja
```

### 步骤 2：注册语言类型

在 `components/locale-provider.tsx` 中：

```typescript
// 添加新语言类型
export type Locale = 'en' | 'zh' | 'ja'

// 导入翻译字典
import ja from '@/data/i18n/ja'

// 注册到翻译映射
const translations: Record<Locale, Translations> = { en, zh, ja }
```

### 步骤 3：添加切换选项

在 `components/LocaleSwitch.tsx` 中：

```typescript
const LOCALE_OPTIONS = [
  { value: 'en', label: 'English' },
  { value: 'zh', label: '中文' },
  { value: 'ja', label: '日本語' },  // 新增
]
```

### 步骤 4：更新 localStorage 校验

在 `locale-provider.tsx` 的 useEffect 中：

```typescript
if (stored && (stored === 'en' || stored === 'zh' || stored === 'ja')) {
  setLocaleState(stored as Locale)
}
```

完成以上 4 步即可添加新语言支持，无需修改任何页面组件。
