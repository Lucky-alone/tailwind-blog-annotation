# 大数据技术概览：Hadoop、Spark与Flink

大数据时代，如何高效处理海量数据是每个技术团队面临的挑战。本文将系统介绍大数据生态系统的核心技术栈，帮助你建立全面的大数据技术认知。

## 什么是大数据

大数据通常用**5V**特征来描述：

| 特征 | 说明 |
|------|------|
| Volume（体量大） | 数据量从GB到PB甚至EB级别 |
| Velocity（速度快） | 数据产生和处理速度极快 |
| Variety（种类多） | 结构化、半结构化、非结构化数据 |
| Value（价值高） | 数据蕴含巨大商业价值 |
| Veracity（真实性） | 数据质量和准确性至关重要 |

## Hadoop：大数据的基石

### 核心组件

Hadoop是大数据生态系统的开山鼻祖，由以下核心组件构成：

**HDFS（分布式文件系统）**

```
NameNode（主节点）    → 管理文件系统的命名空间和元数据
DataNode（数据节点）  → 存储实际数据块
Secondary NameNode   → 定期合并fsimage和editlog
```

**MapReduce（分布式计算框架）**

```python
# MapReduce伪代码示例：词频统计

def mapper(key, value):
    """Map阶段：将文本拆分为单词"""
    words = value.split()
    for word in words:
        emit(word, 1)

def reducer(key, values):
    """Reduce阶段：统计每个单词的出现次数"""
    total = sum(values)
    emit(key, total)
```

### Hadoop的局限性

- MapReduce中间结果写入磁盘，性能受限
- 不适合迭代计算和交互式查询
- 编程模型较为底层

## Spark：内存计算的革命

### 核心优势

Apache Spark通过内存计算大幅提升了大数据处理性能：

- **速度快**：比MapReduce快10-100倍
- **易用性**：支持Python、Scala、Java、R多种语言
- **统一引擎**：批处理、流处理、SQL查询、机器学习一体化

### RDD与DataFrame

```python
from pyspark.sql import SparkSession

# 创建SparkSession
spark = SparkSession.builder \
    .appName("大数据分析示例") \
    .getOrCreate()

# 读取CSV数据
df = spark.read.csv("data/sales.csv", header=True, inferSchema=True)

# DataFrame API操作
# 按产品类别统计销售总额
result = df.groupBy("category") \
    .agg(
        sum("amount").alias("total_sales"),
        count("*").alias("order_count"),
        avg("amount").alias("avg_amount")
    ) \
    .orderBy("total_sales", ascending=False)

result.show()
```

### Spark SQL

```python
# 注册临时视图
df.createOrReplaceTempView("sales")

# 使用SQL查询
top_products = spark.sql("""
    SELECT
        category,
        SUM(amount) as total_sales,
        COUNT(*) as order_count,
        ROUND(AVG(amount), 2) as avg_amount
    FROM sales
    WHERE date >= '2024-01-01'
    GROUP BY category
    HAVING total_sales > 10000
    ORDER BY total_sales DESC
    LIMIT 10
""")

top_products.show()
```

### Spark Streaming

```python
# 结构化流处理示例：实时统计
lines = spark.readStream \
    .format("kafka") \
    .option("kafka.bootstrap.servers", "localhost:9092") \
    .option("subscribe", "user-events") \
    .load()

# 解析JSON数据
from pyspark.sql.functions import from_json, col
from pyspark.sql.types import StructType, StringType, LongType

schema = StructType() \
    .add("user_id", StringType()) \
    .add("action", StringType()) \
    .add("timestamp", LongType())

events = lines.select(
    from_json(col("value").cast("string"), schema).alias("data")
).select("data.*")

# 按5分钟窗口统计用户行为
windowed_counts = events \
    .groupBy(
        events.action,
        window(events.timestamp.cast("timestamp"), "5 minutes")
    ) \
    .count()
```

## Flink：真正的流处理引擎

### Flink vs Spark Streaming

| 特性 | Spark Streaming | Flink |
|------|----------------|-------|
| 处理模型 | 微批处理 | 真正的逐条流处理 |
| 延迟 | 秒级 | 毫秒级 |
| 状态管理 | 有限 | 强大的状态管理 |
| 容错机制 | RDD血统 | Checkpoint机制 |
| 时间语义 | 处理时间为主 | 事件时间 + 水位线 |

### Flink应用场景

- 实时风控：金融交易欺诈检测
- 实时监控：服务器指标告警
- 实时推荐：用户行为分析与个性化推荐
- ETL：实时数据同步与转换

## 大数据技术选型指南

```
数据存储层：
├── HDFS          → 大规模批数据存储
├── Hive          → 数据仓库（SQL on Hadoop）
├── HBase         → 实时读写NoSQL数据库
└── Kafka         → 高吞吐消息队列

数据处理层：
├── Spark         → 批处理 + 微批流处理
├── Flink         → 真正的流处理
└── MapReduce     → 传统批处理（逐步被替代）

数据分析层：
├── Spark SQL     → SQL查询引擎
├── Presto/Trino  → 交互式查询引擎
└── MLlib         → 分布式机器学习
```

## 总结

大数据技术生态庞大且发展迅速。对于大多数场景：

- **离线批处理**：首选Spark，性能优异且API友好
- **实时流处理**：首选Flink，真正的流处理引擎
- **数据存储**：HDFS + Hive/HBase组合
- **消息队列**：Kafka作为数据管道

选择技术栈时，需要根据业务需求、数据规模、延迟要求和团队技术能力综合考量。
